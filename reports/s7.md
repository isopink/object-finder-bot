## Behavior choices

- `find` has two optional keyword arguments beyond the brief:
  `log_path=None` (the JSON-lines log) and `on_status=None` (a callback that
  gets one short English progress line per step; meant for `/objmem/status`).
- Final status when nothing is found: `not_found` if at least one candidate
  was reached and re-checked, `nav_failed` if no candidate could be reached,
  `empty` if `memory.query` returned nothing.
- The `view_pose` retry always happens after a failed first goal, also when
  the first goal already was `view_pose` (a second attempt often succeeds).
- An exception from `navigator.go_to` counts as a failed goal. An exception
  from `verifier.check` (e.g. the worker is down) is recorded as `not_found`
  in `tried`, but `mark_not_found` is not called, because there is no evidence.
  Both texts go to the log (`visits[].error`).
- `nav_failed` never changes the memory.
- `goal_for`: when `view_pose` is already closer to the object than
  `standoff`, the goal is the view position turned toward the object.
- `WhisperSTT.listen()` returns `""` without loading or running the model when
  nothing louder than the threshold was heard (Whisper invents text on silence).

## Search log format (for `scripts/evaluate.py`, Session 4)

One JSON object per line, one line per query:

```
{"query": str, "t_start": float, "t_end": float,
 "status": "found" | "not_found" | "nav_failed" | "empty",
 "found_id": int or null,
 "candidates": [{"id", "label", "sim", "p", "score", "mu": [x, y]}],
 "visits": [{"id", "outcome", "goal": [x, y, yaw], "retried_view_pose": bool,
             "prob": float or null, "error": str or null, "t_start", "t_end"}]}
```

`candidates` is the `memory.query` result in order, with `p` and `mu` as they
were before the visits. `objmem.search.read_log(path)` returns the list of
dicts. If `evaluate.py` expects other field names, adapt it to this or tell me
which side to change.
