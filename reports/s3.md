## Behavior notes

- Server is a single-threaded `http.server.HTTPServer` plus a lock: one request at a time. Errors come back as JSON `{"error": ...}`
  with 400 (bad body / bad image), 404 (unknown path), 503 (no camera or no frame), 500 (exception; server keeps running).
  The client raises `VisionWorkerError` for all of them and for an unreachable worker.
- `/detect_embed` embeds the crop padded by `crop_pad` but reports the detector's own box. When no detector crop survives
  (nothing detected, or all under 10 px) it embeds the 3x3 tiles, labels `tile<r><c>`, conf 0.0. `depth_m` comes from
  `objmem.geometry.median_depth` on the camera's depth image (null in nodepth mode and when an image is sent).
- FakeEmbedder is not random noise: a crop's dominant color maps to a vector close to the text embedding of any sentence
  naming that color ("a red mug"), and gray background crops match the background prompts. So the fake worker answers
  `/verify "a red mug"` -> found and `/verify "a green plant"` -> not found on FakeCamera frames. Other sessions can use this
  in end-to-end tests (e.g. move the red object out of view with `FakeCamera.objects` to make the re-check fail).
- `vision_worker.py`: `--camera` defaults from `camera_mode` (depth -> realsense, nodepth -> c920); `--camera none` serves
  only requests that send an image. Real mode builds `ClipEmbedder`, `make_detector(args.detector)`, `make_camera(kind, width=img_w, height=img_h)`.
  Extra flags: `--host`, `--clip-model`, `--clip-pretrained`, `--no-fp16`, `--verbose`.
- `tune_verify.py --photos DIR --query NAME=TEXT ... [--queries file.yaml] [--fake] [--detector none|detectnet|yolo]`:
  photo object = file stem without a trailing `_<n>`/`-<n>`; prints a per-photo/query table and hit / false-alarm rates for 0.3 to 0.7.
