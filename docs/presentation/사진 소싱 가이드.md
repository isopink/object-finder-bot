# 사진 소싱 가이드

덱의 점선 칸에 들어갈 사진과 영상. 번호는 덱에 나오는 순서. 모두 우리 실험에서 찍은 것만 쓴다(저작권 문제 없음).
넣는 법: PPTX에서 점선 상자를 지우고 그 자리에 사진을 넣는다. HTML은 `assets/`에 파일을 두고 deck.html의 해당 칸을 `<img>`로 바꾼다.

| 칸 | 장 | 찍을 것 | 찍는 요령 | 꼭 |
|---|---|---|---|---|
| 영상 1 | 2 Where Is the Cup? | 데모 한 번 전체: 질문 → 이동 → 좌우 확인 → found | 배속, 40초 안쪽. 노트북 화면(음성 질문)과 로봇이 같이 보이면 좋음. 배속 배율을 대본에 적기 | ✔ |
| 사진 1 | 3 What We Wanted | 통로에 선 로봇과 책상 위 컵 | 사람 눈높이에서, 로봇과 컵이 한 장에 | |
| 영상 2 | 13 Is Probability Worth It? | 컵을 옮긴 뒤 같은 질문 → 옛 자리 → 새 자리 | 데모데이에, 배속 | |
| 사진 2 | 15 Case 1 (a) | 보정 전: 기둥 없이 낮은 로봇 | 옆에서, 바닥 높이. 사진 3과 같은 각도와 거리 | ✔ |
| 사진 3 | 15 Case 1 (b) | 보정 후: 기둥을 세워 높이를 맞춘 로봇 | 사진 2와 같은 자리에서. 책상과 함께 찍으면 높이 차이가 보임 | ✔ |
| 사진 4 | 17 Case 3 (a) | 보정 전 실패한 SLAM 화면 | 화면 캡처. 후보: `assets/map_straight.png`(ㄱ자 → 일자), `assets/map_doubled.png`(벽 겹침) | ✔ |
| 사진 5 | 17 Case 3 (c) | 보정 후 성공한 SLAM 화면 | 화면 캡처. 후보: `assets/room_l4_full.png` | ✔ |
| 영상 3 | 18 Building the Map | SLAM으로 지도를 만드는 과정 | 화면 녹화를 배속, 20초 안쪽. 출발점으로 돌아와 고리가 닫히는 끝까지 | ✔ |
| 사진 6 | 19 Case 4 (c) | RViz에서 AMCL 파티클이 원본 지도 위에 모인 화면 | 화면 캡처 | |
| 사진 7 | 20 Case 5 (a) | 실시간 영상에서 컵 하나에 상자 두 개(몸통, 빨대까지) | 8601 화면 캡처 | |

✔ = 꼭 넣기로 한 것.

설계도(6장)는 `assets/robot_exploded.svg`(원본, 머리글 제거)와 `assets/robot_exploded.png`(덱에 쓰는 그림)로 이미 들어가 있다.
